通过正式代理建立指定域名的 CONNECT 和经过证书校验的 TLS 连接，在保持连接时比较代理进程的内核 TCP 套接字。每个样本只有一个新增外部 TCP 候选；同时按客户端端口关联日志连接 ID，核对域名及出口。接口地址由 ifconfig 交叉确认。耗时包含套接字检查，不是纯网络延迟或视频速度。

CSDN 不在本地手工覆盖名单中：它由国内域名规则库自动匹配，实际连接使用有线，证明自动规则参与了真实请求的分流。

隔离实例：逻辑和故障测试

  • 未知域名解析到国内 IP 时选择有线，解析到境外 IP 时选择 Wi-Fi。测试移除旧静态 IP 列表，使用测试 GeoIP 规则和本地 DNS 数据。
  • 给 GitHub 模拟国内 IP，仍选择 Wi-Fi；给抖音模拟境外 IP，仍选择有线。已知域名归属优先于 IP 推断。
  • 规则更新影响新连接；损坏更新保留有效规则；关闭更新服务器、删除种子文件后仍可从缓存启动。
  • 把隔离实例的境外数据、DNS 和下载接口设为不存在的接口，GitHub 请求失败，真实抖音请求仍能通过有线成功。没有关闭本机 Wi-Fi。
  • 陌生域名返回内网地址时拒绝连接。已确认正式配置等于当前测试构建程序的输出。

实现与验证边界

使用 sing-box 1.14.0，国内外域名和中国 IP 规则库每小时检查更新，按新连接实时匹配。用户选择了“未知域名按 IP 判断”的策略：未知的境外网站使用国内 CDN 时可能被判为国内，反向情况同样存在。混合 DNS 地址也需单独核对。程序不解密网页 TLS，不修改全局路由以学习未知网站。

部署中观察到首次后台更新被网络初始化取消，以及 launchd 重载时序错误。已增加切换前缓存预热和有次数限制的启动重试。缓存和初始规则提供启动保障；若缓存丢失且首次更新失败，使用初始规则，下一更新周期再尝试。这不是“任何情况下永不出错”的保证。

没有完成物理断开 Wi-Fi、高清切换、快进、视频缓冲或长时间播放验收。WebRTC、不遵循系统代理的应用及绕过代理的连接不属于该域名代理的完整覆盖范围。历史 DNS 动态路由的清理仍需按所有权逐项核实，未宣称安全迁移全部完成。
