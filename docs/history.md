### 远程登录方案

当时的分析依据公开的 XNU `xnu-12377.121.6`：
- `tcp_setup_server_socket` 按收到 SYN 的网卡范围查路由。
- TCP 输出使用 `IPOAF_SELECT_SRCIF`，后续查找受源接口约束。
- `rt_lookup_common` 的 scoped 查找会跳过带 `RTF_GATEWAY` 的 lo0 路由；现有掉线阻断使用这种网关路由。

因此撤掉了同日尝试的 pf `reply-to` 方案，代码仍在 Git 历史。该结论来自旧版内核源码分析，并非当前机器物理断开 Wi-Fi 的测试，不能据此承诺任何系统版本下的远程连接都稳定。

SSH 模板、实际远程登录开关、端口转发和登录密钥是不同配置。仓库有模板不代表它们已经启用；当前操作见[可选 SSH](operations.md#可选-ssh)。

### 12:50：DNS 缓存与长连接修复

`0.1.1-independent` 仅替换二进制。DNS 成功结果按 TTL 缓存，最长五分钟；隧道改为两个方向都空闲满五分钟才触发关闭，避免单向安静误伤持续下载。

当时 GitHub 重复 CONNECT 约 270 ms，原来每次约 515–647 ms。60 KB/s 限速下载在 400 秒测试期间保持上游连接；旧 `0.1.0` 在第五分钟发送 FIN，随后约 80 秒被服务器关闭。这验证了该故障场景，不代表任何长连接都不会断开。

### 21:25：Python 运行组件迁入 Go

地址策略、DNS 观察、配置生成和部署工具迁到 `engine/`。上线后观察服务运行 Go 二进制，旧 Python 系统程序被移除；两份 zsh 路由守护仍保留。迁移解决的是运行组件对可由普通管理员账户改写的 Python 安装的依赖，不是“所有组件都不再使用解释器”。

### 21:46：减少规则重复下载

`0.1.2-independent` 加入 ETag 条件请求。规则未变化时不再每小时重复下载完整数据；当时核对抖音和哔哩哔哩使用有线、GitHub 使用 Wi-Fi。
