# 双线分流概览

## 核心要求

- 境外网站使用 Wi-Fi；Wi-Fi 不可用时，不回落到有线访问境外。
- 国内网站使用有线；Wi-Fi 掉线不应阻断正常的国内有线访问。
- 代理域名分流与系统 IP 路由是两层机制，需要分别验证，不能仅凭状态页显示 OK 判断全部正确。

## 程序分工

| 组件 | 职责 |
| --- | --- |
| `network-domain-engine` | 自研 Go 代理核心，按规则选择网卡 |
| `network-split-dns-event-route-agent` | 读取 DNS 事件，维护授权的国内地址路由 |
| `network-split-policy` | 统一判断地址是否允许走国内有线 |
| `network-split-health` | 独立的 Go 健康检查入口，复用调度、锁和状态回收逻辑 |
| `network-split-status` | 只读采集 DNS、IP 路由及 HTTP 响应，生成本地 HTML |
| `network-domain-proxy-deploy` | 人工授权的部署和维护，不作为新版定时健康入口 |
| 现有两个路由守护 | 仍为 zsh；保留路由修复和境外回落阻断 |

源码更新不等于线上切换。健康入口与状态页更换后，必须核对实际 launchd 参数、安装文件哈希和新一轮任务结果。

## 安全与日志

- DNS 守护不再从用户可改写的 Homebrew 目录自动恢复并执行程序。固定程序异常时报警，等待管理员安装可信程序。
- 状态页只取境外响应头，连接绑定 Wi-Fi；HTTP 403/404 能证明收到了响应，但不能证明应用可正常使用。
- 新状态程序按固定上限维护自身日志：每份不超过 1 MiB，最多保留三份归档。迁移前已有的大日志必须先保留到本机私有位置，不自动截断。
- HTML、运行状态、旧日志和本机配置不上传公开仓库。停用组件要先检查引用，不能只凭名称删除。

## 验证和发布

GitHub Actions 使用 macOS 和固定版本 Go，检查竞态、静态问题、离线集成及已有路由测试。不接触本机网络，不自动部署。

管理员权限只通过 macOS 授权窗口取得，密码不进入聊天。上线按预检、原子替换、验收执行；失败回滚。代理、DNS 和观察服务的重启应是明确操作，而不是维护工具升级的附带效果。

详细命令与历史验收见 [项目说明](../README.md) 和 [引擎说明](../engine/README.md)。
