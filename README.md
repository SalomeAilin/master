# 双线网络分流

境外网站走 Wi-Fi，国内网站走有线。代理连接绑定对应网卡，境外连接失败时不回落到有线。

这是当前使用的源码与配置仓库，不只是安装文件的备份。自研 Go 引擎不导入或运行 sing-box；dnsmasq 和两份系统路由守护仍是独立组件。

## 程序分工

| 部分 | 当前职责 |
| --- | --- |
| 自研代理核心 | HTTP、CONNECT、WebSocket 和 SOCKS5 TCP 的域名分流 |
| Go DNS 观察服务 | 从 DNS 查询日志识别国内地址，交给统一地址策略审核后维护路由 |
| Go 地址策略 | 判断哪些 IPv4 地址允许增加国内有线路由，不是常驻服务 |
| Go 健康检查 | 独立程序，每 30 秒被唤起；实际 HTTP 探测间隔为 30、60 或 120 秒 |
| Go 状态页 | 现有用户任务每 5 分钟运行一次，生成本地 HTML，不修改网络 |
| 两份 zsh 路由守护 | 维护默认路由、国内路由与 Wi-Fi 掉线时的境外阻断 |
| dnsmasq | 单独安装的 DNS 解析器，不是本仓库编译的 Go 程序 |
| Go 配置、部署、取证工具 | 按需执行；部署和部分取证操作需要管理员授权 |
| 三份 Shell 安装工具 | 保留给 DNS 初始化、批量安全更新及可选 SSH 配置，不是额外的后台任务 |

具体程序名、源文件、安装路径和任务标签以[组件清单](docs/operations.md#组件清单)为准。旧部署工具的 `health-check` 只是兼容命令，定时健康任务已经使用独立程序。

## 分流边界

- 已知域名先按域名规则判断；未知域名才通过解析出的公共 IPv4 地址推断线路。CDN 所在地不一定等于网站归属，不能承诺所有未知网站都判断正确。
- 代理使用内核网卡绑定；不经过代理的连接仍由系统 DNS 和 IP 路由处理，两层机制需要分别验证。
- Wi-Fi 掉线时阻止境外流量走有线是既定策略。系统路由守护是周期任务，不能把代理的即时绑定约束等同于所有直连程序都能即时阻断。
- 状态页的 OK 只表示当次样本通过。HTTP 403/404、首页可达、测试通过，都不能证明应用功能、视频播放或长期稳定性。

## 文件放在哪里

| 目录或文件 | 内容与处理方式 |
| --- | --- |
| `engine/` | Go 源码及包内测试 |
| `config/` | 生效配置的来源、规则输入及明确标注的可选配置 |
| `config/launchd/` | 系统任务定义；带用户路径的状态页 LaunchAgent 留在本机 |
| `scripts/` | 两份运行中的路由守护和三份人工安装工具 |
| `tests/` | 现有离线路由及安装回归测试 |
| `docs/` | 当前操作说明与历史验收索引 |
| `archive/` | 公开的历史快照、旧验收材料和许可证，不是部署输入 |
| `local/docs/` | 私人文档，不公开、不当作缓存清理 |
| `local/archive/` | 私有历史源码、备份、日志和缓存，按来源分类保留 |
| `assets/images/` | 项目图片，不是运行组件 |
| `.github/workflows/` | GitHub 自动测试 |
| `network-split-status.html` | 现有任务的固定输出，留在根目录并忽略 |

源码目录和系统安装目录用途不同，不是可随意删除的重复文件。历史目录也不等于“可以清空”：移动前核对引用，删除前确认归属和恢复用途。

## 检查与变更

GitHub Actions 在 macOS 上执行 Go 竞态检测、`go vet`、离线集成测试和四组既有 Shell 回归测试。它不连接本机生产环境，也不自动部署。[本机验证命令](docs/operations.md#验证)使用同一套检查。

日常维护优先使用现有 Go 命令。修改源码、推送 GitHub 和替换线上程序是不同步骤；系统部署必须经过管理员授权，并核对实际文件与新一轮任务结果。密码只在系统授权窗口或本机终端输入。

Wi-Fi 按流量计费，境外后台探测保持低频、只取响应头；不要另加重复保活任务。DNS 程序缺失或权限不符时，路由守护只报警，不从用户可改写的 Homebrew 目录自动复制并执行程序。

日志、机器专用路径和诊断原始数据保留在本机。各日志的上限和轮转条件见[日志与状态](docs/operations.md#日志与状态)，周期轮转阈值不能当作即时硬上限。
